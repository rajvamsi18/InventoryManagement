# SMKG Frontend

## Purpose

The `frontend/` folder contains the installable, offline-first React PWA for SMKG (Sri Mareswari Kirana & General Stores). It is built with React, TypeScript, Vite, Dexie, and `vite-plugin-pwa`.

## Local Data

The app uses the browser's IndexedDB via Dexie. It creates a `grocery-inventory` database on the device. Version 11 contains:

- `products`: stock, brand, category, pack size, measurement unit, package type, supplier-batch stock lots, expiry, GST, image, cost, margin, selling price, and timestamps.
- `orders`: submitted sales orders.
- `orderItems`: products, selling prices, and cost snapshots used for realized-profit reporting.
- `productOptions`: owner-managed categories, brands, measurement units, and package types.
- `onlyOrders`: independent orders with embedded free-text product/Volume lines, quantities, prices, and totals. Never included in inventory stock, sales metrics, or catalog queries. Backup v6 includes this table and imports v1-v5 compatibly.
- `customers`, `creditOrders`, `creditPayments`, `creditAdjustments`: customer-level credit accounts and their ledger/void records, separate from inventory and Only Orders.
- Customer deletion records a non-indexed `deletedAt` marker and `updatedAt` in the existing store, requiring no schema-version change. List queries exclude deleted customers; linked ledger/audit records remain intact. Individual bins and long-press checkbox selection work in Active and Archived directories. `deleteCreditCustomers` checks all selected balances and writes markers atomically; any nonzero or missing account rejects the entire selection. Backup v6 preserves deleted markers and their references.
- `creditHistory`: append-only edit/void snapshots linked by `customerId`, `targetType`, and `targetId`, with timestamps, action, reason for voids, and full before/after records for edits. Financial edits retain transaction IDs/numbers and do not generate replacement orders/payments. This table is included in backup v6.

Data persists across refreshes and offline use, but site-data clearing can remove it. The app includes JSON backup export/import. A backend sync will provide an additional Postgres backup later.

## Views

- **Home**: products, sales today/month, units sold today, and sales snapshot. Low-stock products appear in a clickable table that opens product details.
- **Products**: searchable catalog with 12 products per page. Search covers product name, brand, MRP, combined pack size/unit, category, measurement unit, and package type. Selecting a product opens stock, pricing, profit, sales, and order history details.
- **Inventory**: add and edit stock, manage catalog options, and import/export backups. Each configurable product dropdown has an Add new shortcut that opens/focuses the matching Catalog options section, preserves form input, and selects the newly added value automatically.
- Stock and inventory-linked order quantities use whole sellable units. Only Order quantities accept positive finite decimals without changing stock. Pack size remains decimal-capable for weights and volumes such as 0.5 kilograms. IndexedDB v8 normalizes legacy fractional/negative stock to the nearest non-negative whole unit.
- **Voice-assisted basket entry** (`VoiceOrderAssistant.tsx`, `services/voiceOrder.ts`): feature-detects the Web Speech API (`SpeechRecognition`/`webkitSpeechRecognition`) and renders nothing when unsupported. Supports English (`en-IN`) and Telugu (`te-IN`) via a toggle. Recognition is continuous with a manual stop so a full sentence isn't cut off at a pause. Parses quantity, product name, pack size/unit, package type, unit cost, profit margin, and selling price (deriving selling price from cost+margin when not stated), ranks catalog matches by word overlap, and shows a "Detected for new product" review of every field before requiring a manual confirm tap. Falls back to prefilling Inventory's Add new product form with all detected fields when no product matches. Requires network connectivity because browser speech recognition is cloud-based.
- **Selectable voice engine** (`services/voiceSettings.ts`, `services/sarvamStt.ts`): a Browser/Sarvam toggle next to the language switch, persisted in `localStorage`. Browser uses the built-in Web Speech API above at no cost. Sarvam records audio with `MediaRecorder` and posts it to a Cloudflare Worker proxy (see `/worker`) that holds the Sarvam API key server-side and forwards to Sarvam's speech-to-text API; the worker URL is read from `VITE_SARVAM_PROXY_URL`. If that env var isn't set, choosing Sarvam shows an inline "not configured yet" message instead of failing silently. Sarvam also works on devices without Web Speech API support (e.g. iPhone Safari), since it only needs microphone recording.
- **Sales**: Sales opens an **Orders** landing page with vertically stacked **From Inventory**, **Only Order**, and **Credit Order** buttons. Selecting a flow reveals inline **All Orders** and **Create Order** choices (no chooser popup) in a consistent layout. From Inventory keeps the catalog basket and stock-linked order flow; Only Order opens `OnlyOrdersPage.tsx`, an independent create/list/detail/edit/delete flow. Credit Order opens the customer/account ledger in `CreditOrdersPage.tsx`.
- **Order history**: Each flow has a separate All Orders view, a back-to-Orders action, and independent 5/10/20-order pagination. Only Order history adds From/To dates and Today, Last 7 days, Last month, and All dates presets; its order count, average, total, **Top Customer** and visible list respond to the selected date range, with search further filtering the list. Top Customer is the named customer with the highest spend in that range. Search matches order number (with or without spacing), customer name, date, and exact order amount. Rows show customer names below order numbers. Long press enters checkbox selection mode; one selection can be edited/deleted, while multiple selections can be deleted together with stock restoration for inventory orders.
- **Credit Orders** (`CreditOrdersPage.tsx`, `services/creditOrders.ts`): an independent Sales flow with **With list** (WhatsApp Read List drafts) and **Without list** manual entry; both use free-text products and do not alter inventory. Tap activity rows to edit; long press enables checkbox multi-selection and atomic bulk voiding from the header bin, with individual row bins also available. Edits update the same record and append before/after snapshots in `creditHistory`; voided originals are hidden from normal activity without discarding history. Order editing supports saved source-message comparison/edit/delete and adding messages without replacing existing priced lines. Customer archive uses an in-app confirmation, requires zero balance, and supports restore. All back links have space below the tabs. Balances derive from non-voided transactions, and overpayments are rejected. Backup v6 includes credit data and audit history while v1-v5 imports remain supported. Credit limits, due dates, interest, and per-order payment allocation are out of scope for v1.
- **Order modes**: `OrderHistoryHeader.tsx` owns the shared inline flow choices. Create Order in Only Order reveals inline **From list** (the existing WhatsApp Read List flow) and **Without list** manual-entry actions; Read List’s message-entry dialog remains. From Inventory Create Order continues into the existing catalog basket. `services/onlyOrders.ts` validates positive finite quantities (including decimals) and non-negative finite prices/totals, derives price/total bidirectionally, and writes only to `onlyOrders`. Number allocation is inside its transaction; Only Order labels use `OR N`, with legacy padded labels normalized for display. Only Order receipt lines map into the shared PDF service without being persisted in `orderItems`. Product and voice-review labels use Volume instead of Pack size; inventory field storage is unchanged.
- **WhatsApp Only Order import**: Read List accepts pasted text and creates an unsaved Only Order draft using the Cloudflare Worker's `/read-list` route and Workers AI (`@cf/qwen/qwen3-30b-a3b-fp8`). Use **Add another message** to parse later customer messages into the same order; existing lines, edits, and prices remain intact, and every source message stays available for comparison. On a saved order, choose **Edit order** to edit/delete source messages; changes are committed together with the normal **Save order** action. Editing a source replaces only its linked rows, preserving manually entered prices for unchanged product/Volume matches; new or changed rows have blank prices. Deleting a source removes only its linked rows. Exact duplicate messages prompt before extraction; choose whether to add them again or cancel. Clear size descriptors (for example, “big plastic bags”) are requested as Volume (for example, “Big”) instead of being kept in the product name. The model receives no inventory records or prices; imported Price and Total remain blank. An omitted or unclear quantity defaults to `1` with an `AI assumed 1 · review` marker that clears when the quantity is edited. Extraction may still omit or misname a product. Review/correct all lines and enter prices before submitting. The text is sent only after Read list is tapped, and is not saved as an order before submission. Android Chrome can share text into an installed PWA; iPhone users can copy/paste. Parsing needs internet; manual entry remains available offline. See `worker/README.md` for provider limits and deployment configuration.
- **Customer names**: Both order creation/edit flows accept an optional customer name. It is persisted on the order, displayed below the order number in history/details, and included in receipt previews/PDFs; old orders without a name remain valid.
- **Receipts** (`OrderReceipt.tsx`, `services/receipt.ts`): successful submission opens saved order details. New and existing orders support a receipt preview, A5 PDF download, and Web Share with download fallback. A centered, rounded-outline **Order Receipt** title sits above SMKG. Store details include the supplied address, labeled contact, GSTIN, Composition Dealer status, and `kanamahalakshmi.jpg`. Product names are bold in both preview and PDF. On mobile the store title is 15px and the deity image is 1.5px taller; the PDF uses a matching modest size increase. PDFs use persisted order lines rather than mutable catalog prices, exclude costs/margins, show India time, and paginate long orders. The receipt bundle is lazy-loaded and precached for offline use. WhatsApp is selected manually from the OS share sheet; actual device sharing requires manual verification.

## Run and Test

Credit Order entry/editing uses a two-line order-number/customer identity. Account activity omits product summaries and reuses `OrderHistoryPagination` with an Entries label; customer lists use Customers. Active and Archived lists retain independent page/page-size settings. Activity pagination is scoped to the selected customer, clamps after deletion, and clears selections when navigating pages. Shared pagination defaults remain unchanged for inventory and Only Order history.

Payment editing uses the same compact identity treatment with its payment number. The balance and edit limit are separate paragraphs; payment footer actions use an equal-width, equal-height two-column grid. The Credit Order landing wrapper uses block flow (not the inner-page grid gap), matching the other two Sales landing layouts without shifting the choice panel.

Customer account management links use a separate row between the identity header and metrics. The Credit Order / Record Payment actions below the metrics share a two-column grid with matched padding, borders, and 44px height, including the disabled payment state. Archived accounts instead expose Restore customer above the metrics.

Credit account activity uses order-number-only purchase labels and signed two-decimal amounts without currency prefixes. Customer list balances, the Outstanding balance metric, and payment balance/edit-limit paragraphs also omit `Rs.`; other flow/receipt formatting remains unchanged.

Only Order's mobile and desktop Quantity inputs use decimal keyboards, `step="any"`, and validation requiring a finite number greater than zero. Persistence and backup validation accept fractions, while inventory-linked quantity rules remain unchanged. Tests cover `1.25 * 65 = 81.25`, `0.25 * 65 = 16.25`, reverse price derivation, decimal saves/edits, backup acceptance, and decimal receipt output.

PDF receipts use pdfmake with bundled Noto Sans and Noto Sans Telugu regular/bold fonts. Script-aware font runs preserve Telugu grapheme clusters for OpenType shaping and retain Latin glyphs in mixed names. `createReceipt` is asynchronous; `OrderReceipt` prepares a keyed PDF for the current order/customer before enabling Download/Share, so no async generation happens between the Share tap and `navigator.share`. Stale generation results are discarded. Workbox explicitly precaches TTF files and the public OFL license. Regression tests read generated PDFs with PDF.js and cover English/Telugu text, embedded fonts, privacy, amounts and pagination. Visual rendering was inspected with system-font fallback disabled, and production cold generation/share succeeded with the preview server stopped after precaching. The larger PDF renderer remains lazy-loaded with the receipt UI.

Only Order display and saved numbering now use `OR N`; legacy labels normalize on display/edit, including receipt titles. Only Order history reuses `OrderRow` long-press selection, checkbox/select-all controls, and contextual single-edit/bulk-delete actions. `deleteOnlyOrders` deletes only from the independent table. Shared row checkboxes stop pointer/keyboard propagation so clicks toggle once rather than also activating the row. Detail actions have dedicated compact styles instead of inheriting the receipt toolbar's mobile stretching.

`MobileOnlyOrderEditor.tsx` is selected at widths up to 700px using a subscribed media query. It uses a native modal dialog styled as a bottom sheet, a separate temporary product draft, existing `updateOnlyOrderLine`/`parseOnlyOrderLines` validation, compact editable rows, and safe-area-aware fixed actions. Only committed draft rows are passed to order submission; cancelling a sheet does not mutate them. Wider screens retain the desktop editor. Browser checks cover Add & next, row editing/cancellation/deletion, submission and saved-order edits, receipts, 320/390px layouts, a shortened viewport, and switching back to the desktop grid.

Receipt product labels include pack size and measurement unit in preview and PDF. New sales snapshot `measurementValue` and `unit` on order items (optional non-indexed fields, no IndexedDB version change needed). Legacy receipts fall back to the linked product's current pack details. Recorded values take precedence over later catalog changes.

```bash
cd frontend
npm install
npm run dev
npm run build
npm run test:receipt
npm run test:only-orders
npm run test:credit-orders
npm run lint
```

The Worker has a separate focused suite: `cd worker && npm ci && npm test`.

`npm run build` performs the TypeScript check, production Vite build, and PWA service worker generation.

## PWA Deployment

The GitHub Actions workflow in `.github/workflows/deploy.yml` builds `frontend/` and deploys it to GitHub Pages when `main` changes. The Vite base is relative (`./`) so the deployed PWA works under a repository path.
